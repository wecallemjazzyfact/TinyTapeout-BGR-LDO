## 0. ★ 좌표 규율 (최우선)

**셀 중심은 반드시 magic 실측으로 확인한다.**

```tcl
select clear
select cell <인스턴스명>
box
```

- `.mag`의 `transform` 값은 파일·시점에 따라 ÷100 / ÷200 해석이 갈려 **판독 착오가 반복 발생**했다.
- **DRC 에러 마커(`error_p` 등)가 bbox를 부풀린다.** 마커 있는 셀은 중심 오프셋이 실제 확산 기준보다 크다. 마커는 셀 단독 DRC 실행 시 재생성되므로 배치 완료 후 일괄 삭제한다.
- **실제 사고**: 행 B(`3XTGEW`)의 중심을 마커 없는 값(LL+1.47)으로 계산해 배선한 결과, riser가 게이트 스트랩과 정확히 맞닿아 **13개 소자 전부 G-S 단락**. DRC는 침묵(touching = 병합).

### 서펜타인 기하 모델 (실측)
- `l_ext = 8·L_col − 0.27` (N=8)
- 높이: 짝수 N → `L_col + 2.68` / 홀수 N → `L_col + 5.36` (**N=2에서도 검증됨**)
- 폭: N=8 → 8.88, N=2 → 1.86 (컬럼 피치 1.17, 폭 0.69, 컬럼 간 갭 0.48)
- 단자: 중심 ±(폭/2 − 0.345), y = LL + 0.175. met1 패드 0.59 폭 × 2.045 높이

### ★ 변경 금지
- **분할 수**(R6/R7만 2분할, R2fix 통짜) — 헤드 TC 2성분 모델. 쪼개면 TC 이동
- **N=8 통일** — 코너 개수 비가 깨짐. 길이는 `L_col`로만 조절

### 더미 규격 근거
- 폭은 줄여도 되나(N=2), **높이는 실소자와 반드시 동일**. 짧으면 가장자리 컬럼의 위아래 환경이 달라져 한 컬럼 안에서 W_eff가 y에 따라 변한다
- N=1(직선)이 아니라 N=2인 이유: N=1은 높이가 `L+4.16`이라 실소자와 어긋난다
- 어레이 전체가 **1.17 균일 격자**가 되도록 배치 (피치 9.36 = 8.88 + 0.48)

## 7. magic 함정 (실증)

1. **`erase <층>`은 contact type의 해당 성분과 인접 도형을 깎는다.** via1의 met1 성분 파괴, li 스텁 절단, 링 met1 0.02 부족 등 반복 발생. **erase 후 반드시 재검산·재도포.**
2. **`select area` + `delete`는 박스에 걸친 도형을 통째로 삭제**한다 (met3 L자 소실 사례).
3. **같은 넷이어도 애매하게 떨어지면 `met1.2` 위반.** 붙이거나 0.14 이상 띄우거나 둘 중 하나.
4. **넷 카운트만 세면 단락을 놓친다.** 추출 검증은 반드시 **4포트 전부 출력**해서 확인. (G가 S와 같은 넷인데 카운트만 보고 통과 판정한 사고 2회)
5. `label`은 점 박스 + 단일 층 위에서만. 중복 시 `_uq0` 접미어 발생.
6. gencell: 가드링 끄면 nwell·탭 소멸(상위에서 일괄), 해시명은 파라미터별 발급·재생성 시 변경.
7. `drc catchup`이 실제 검사를 실행. `drc find` + `box`로 에러 위치 순회.
8. 서펜타인 추출 시 `Device has multiple lengths` 경고는 무해(LVS는 W/L 비교). 단 **PEX 저항값은 이 환산으로 결정**되므로 post-layout 확인 필요.
9. magic tech의 xhrpoly 시트저항 **319.8** vs ngspice 정본 **325.0** (+1.22%) — LVS 무해, PEX 주의.
